# OneHZ 1.3.0-rc.1

Local release candidate for the 1.3.0 line. It is not published; the stable 1.3.0 follows
the screen-off and Samsung validation gate.

## Highlights

- **Quick controls.** One-hour master pause, a Quick Settings tile, a foreground
  notification with the active profile/rate and pause/resume/disable actions, and launcher
  shortcuts for pause, Economy and diagnostics.
- **System changes.** A screen lists the keys OneHZ writes, the current and captured
  original values, an explicit restore-all action, an external-change warning from the
  session audit, and a sanitized panel report export.
- **Usage.** Time per applied rate, Always On Display and uncontrolled time, plus the
  profile split, for today and the last seven days. Event-driven, local, pruned after
  30 days.
- **Activation rules.** Low-battery guard with hysteresis, charging and a time window, all
  pointing at saved profiles and evaluated without polling.
- **Per-app targets.** Each app can follow a profile, pin a fixed rate or hand control back
  to the system. Profile schema 2 reads schema 1; backups use schema 2 with the same
  compatibility.
- **Suggestions.** The Apps screen suggests unassigned games, players and camera apps.
- **Automation.** Explicit pause/resume/profile/toggle broadcasts for automation tools.
- **AOD (Samsung).** A night brightness schedule evaluated at lock time inside the safety
  band, and a reapply of the AOD rate after a Doze maintenance window.

## Upgrade and data

Install over 1.2.2-beta.1. The signing key is unchanged. Profile and backup schema 2 read
schema 1. Profile duplication and delete undo are available in Manage profiles.

## Validation gate

Before 1.3.0 is final, the user validates on the POCO and the Samsung:

- POCO: lock/unlock with the AOD rate, pause across screen off, activation rules, usage
  buckets and Sleep/Doze regression.
- Samsung: AOD brightness, the night schedule inside and outside the window, the safety
  band, restore-all and the rate/AOD regression.

The build is signed and installed locally; no tag, push or release is created from this
candidate.

## Known limitations

- AOD brightness and its schedule are Samsung-only.
- The AOD schedule is evaluated at lock time; changing the window applies on the next lock.
- Per-app usage attribution is not collected; it would require reading the foreground app
  continuously.
- PiP is detected from the pinned task; it is treated as video when the foreground app has no playing signal.
- The 30 Hz panel dimming on the tested POCO remains a hardware limitation.

# OneHZ 1.3.0

Stable release focused on day-to-day control, transparency and local data.

Available from **Shizu Store**, GitHub Releases and Obtainium. OneHZ is not on Google
Play.

## Highlights

- **Quick controls.** A one-hour master pause that restores the system values and resumes
  on its own, an on/off Quick Settings tile with an **Add tile** action in Settings, a
  state-aware foreground notification with pause/resume/disable, an optional **Pin
  notification** switch (off by default; on Android 14+ a swipe is restored right away), and
  launcher shortcuts for pause, Economy and diagnostics.
- **System changes.** A screen lists the keys OneHZ may write, the current and captured
  original values, an explicit restore-all action, an external-change warning from the
  session audit, and a sanitized panel report export.
- **Usage and Doze.** Usage shows time per applied rate, Always On Display, uncontrolled
  time and the profile split for today and the last seven days. It also hosts the
  Sleep/Doze summary and session history; the Sleep detail keeps a compact summary and
  links here.
- **Activation rules.** Low-battery guard with hysteresis, charging and a time window, each
  pointing at a saved profile. The active layer is visible in Diagnostics.
- **Per-app targets.** Each app can follow a profile, pin a fixed rate or hand control back
  to the system. The battery-saver exception is also available when an app is added, and the
  row shows **Keeps its profile** when it applies. Profile schema 2 reads schema 1; backups
  keep the same compatibility and a schema 1 copy is kept before the first schema 2 write.
  Activation rules are included in backups.
- **Suggestions.** The Apps screen suggests unassigned games, players and camera apps.
- **Picture-in-picture.** The engine reads the pinned task and keeps the video floor while a
  PiP window is visible.
- **Automation.** Explicit pause, resume, profile and toggle broadcasts for automation
  tools.
- **AOD (Samsung).** A night brightness schedule evaluated at lock time inside the safety
  band, and a reapply of the AOD rate after a Doze maintenance window.

## Upgrade and data

Install over 1.2.1 or any 1.2.2 beta (beta.1 or beta.2). The signing key is unchanged and
settings are kept. Profile and backup schema 2 read schema 1. A one-time
`profiles-schema1.json` copy is written to the app external files directory before the first
schema 2 save.

> **Downgrade warning.** A 1.2.x install cannot read schema 2 profiles. Export a backup
> before downgrading.

## Verification

- Tested on a POCO X7 Pro (`2412DPC0AG`, Android 16 / HyperOS 3): quick controls, tile,
  notification, system restore, Usage/Doze, activation rules, per-app targets, picture-in-
  picture with YouTube, migration from schema 1 and performance.
- The Samsung AOD brightness and night schedule are hardware-specific; verify them on the
  target Samsung device.

## Known limitations

- AOD brightness and its schedule are Samsung-only.
- The AOD schedule is evaluated at lock time; changing the window applies on the next lock.
- Per-app usage attribution is not collected; it would require reading the foreground app
  continuously.
- The 30 Hz panel dimming on the tested POCO remains a hardware limitation.
- Baseline Profile was generated before this work and is slightly stale; it remains valid.

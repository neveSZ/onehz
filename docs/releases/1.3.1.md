# OneHZ 1.3.1

Stable release focused on resource use and on notification control, without changing the
control model: Shizuku, the same allowlists and the same fail-closed rules.

## Highlights

- **Notifications in Settings.** Settings → Quick controls → **Notifications** shows whether
  OneHZ can post its notification and requests the permission or opens the system page.
  Previously this was only reachable from the setup screen.
- **Optional refresh rate.** **Show refresh rate** keeps the profile and the applied rate,
  or only the profile. Rate updates are coalesced to one per second; state changes (pause,
  AOD, idle, profile) are immediate.
- **Pin and rate options require notifications.** Both are disabled while OneHZ
  notifications are off, and the stored pin is cleared in that case.
- **AOD text.** While the screen is off the notification now reads **AOD · 10 Hz** instead of
  "Inactive".
- **A notification hidden by the system is not a dismissal.** Enabling access again restores
  the notification instead of leaving it frozen.
- **Battery optimization warning.** While notifications are on and OneHZ is still optimized,
  Settings → Quick controls warns that background notification updates may lag. **Allow**
  opens the system exemption dialog; the first visit also asks once, and **Not now** keeps
  only the warning. On HyperOS, set **No restrictions** and **Autostart** as well.
- **Video follows the foreground app.** Leaving a video app for an audio app no longer keeps
  the video floor until the next touch, even without per-app assignments.
- **Paused video releases the floor.** The media-session parser also reads the sessions-stack
  format used by Android 16 builds, so a paused player stops counting as video until
  playback resumes. The same applies to a paused picture-in-picture window.

## Performance

- The profile JSON, activation rules and the vendor/rate detection are cached and only
  rebuilt when their source changes; the caches are cleared on a configuration change.
- Reopening the app reconciles state + foreground/video at most once every five seconds; the
  session audit runs at most every fifteen seconds.
- Video probes are combined: one activity dump serves foreground and PiP, the other dumps
  are parsed in-process, a positive verdict is reused for ten seconds and the touch-down
  probe is gone.
- AOD brightness ignores targets within two raw units, uses a 600 ms debounce and no longer
  reads the key back after writing it.
- System changes and the diagnostics actions no longer run privileged shell reads on the
  main thread.
- The privileged service uses one watchdog thread for command deadlines and monitor
  restarts, decodes command output without an extra copy, and no longer compiles regexes per
  call or per `ps` line. TTLs use the monotonic clock.
- App icons use a 96-entry LRU; the diagnostics log reuses its formatter and filter.

## Upgrade and data

Install over 1.3.0 or 1.2.x; the signing key is unchanged. Profiles, assignments, Sleep
records and backups are preserved. There is no schema change in this release. The
notification preference is not part of the backup, like the pin.

## Verification

- Installed over 1.3.0 on a Galaxy S25+ (Android 17 / One UI 9) and a POCO X7 Pro
  (Android 16 / HyperOS 3).
- Notification access enabled from Settings on both devices; rows gated correctly with the
  access disabled; pin/rate disabled and the stored pin cleared.
- Texts observed: profile only (`Equilibrado`), profile plus rate (`Equilibrado · 90 Hz`,
  `Equilibrado · 10 Hz`), AOD (`AOD · 10 Hz`).
- Video: YouTube playback raised the HyperOS rate cap to 60 Hz and the notification followed.
- Profile switch by automation (`SET_PROFILE`) updated the notification and the applied rate
  without a restart; the Apps screen listed 85 apps.
- Per-app target (POCO): a fixed 60 Hz assignment for YouTube Music applied with battery saver
  off; the automatic Economy profile overrode it with the saver on, and **Keep this app's
  profile during battery saver** made the fixed rate win again. Assignment removed afterwards.
- Backup and restore (POCO): exported a 2,982-byte JSON, switched the selected profile to
  Performance, imported the file and the profile returned to Balanced with the same
  assignment count; Sleep settings were restored as reported.
- Quick Settings tile (POCO): added, toggled control off (rate restored to 120 Hz, notification
  removed), toggled back on, and the Settings row switched to **Tile added**.
- Restore on disable: the tile and the toggle both returned the vendor key to its original
  value and removed the notification.
- Fail-closed and Doze (POCO): killing the Shizuku server stopped control and showed
  **Inactive**; the engine reconnected on its own when the service returned. Sleep forced
  `mState=IDLE` on screen off and `ACTIVE` on screen on; the device was left with Sleep off.
- System changes opened with the asynchronous load and showed the current/original keys.
- Battery optimization warning: with the exemption removed the warning and the one-time prompt
  appeared on both devices, **Allow** opened the system dialog, and the warning disappeared
  after granting. With notifications off the warning stayed hidden; the exemption was restored
  on both devices afterwards.
- AOD brightness deadband (S25+): screen brightness 200 wrote 20/255 to the AOD key; 210
  (a target one unit away) kept 20; 250 wrote 25. Screen brightness, its mode and the key were
  restored afterwards.
- Video on the POCO (HyperOS 3): playback raised the floor to 60 Hz from the 30 Hz resting
  tier; pausing released it back to 30 Hz within 5 s; YouTube Music playing without a PiP
  stayed at 30 Hz; a playing PiP kept the 60 Hz floor and a paused PiP released it.
- `:app:testDebugUnitTest`, `:app:lintRelease` and `:app:assembleRelease` pass.

## Known limitations

- AOD brightness and its schedule are Samsung-only.
- The 30 Hz panel dimming on the tested POCO remains a hardware limitation.
- On HyperOS the vendor power manager keeps its own restrictions, so the app also points to
  **No restrictions** and **Autostart** in the app settings.

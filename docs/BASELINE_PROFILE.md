# Baseline Profile

OneHZ ships a Baseline Profile so ART can ahead-of-time compile the startup path and the
most used screens. The profile is installed by `androidx.profileinstaller` and is also
picked up by `adb shell cmd package compile -m speed-profile`.

## Layout

- `baselineprofile/` — `com.android.test` module with the Macrobenchmark generator.
- `app/src/release/generated/baselineProfiles/baseline-prof.txt` — generated profile,
  consumed by the release build. Commit this file.
- `app/src/release/generated/baselineProfiles/startup-prof.txt` — startup subset
  generated by the same run. Commit it too; the build uses it when available.

The `androidx.baselineprofile` Gradle plugin wires the `benchmark`/`nonMinifiedRelease`
variants and adds the `generateBaselineProfile` tasks.

## Regenerate

Requirements: a physical device or emulator running API 31+, screen unlocked, USB
debugging or wireless debugging enabled.

```bash
./gradlew :app:generateReleaseBaselineProfile
```

This installs the `io.github.nevesz.onehz` build signed with the debug key. If the
installed app is signed with the release key, uninstall it first or use a device where
the app is not installed, because Android refuses signature mismatches.

The task may uninstall and reinstall the app under test, which **erases its data** (and
the Shizuku grant). Export a backup first if the device holds real configuration. On
HyperOS/MIUI, the first installation via ADB shows an "Install via USB" confirmation on
the device; accept it (and "remember my choice") or the run ends without tests.

The task runs the scenarios in
`baselineprofile/src/main/java/io/github/nevesz/onehz/baselineprofile/BaselineProfileGenerator.kt`,
writes the profile, and copies it into `app/src/release/generated/baselineProfiles/`.

## When to regenerate

- Startup flow, theme, or navigation changes.
- Home/diagnostics screens change substantially.
- Compose, Lifecycle, or other startup-critical dependencies are upgraded.

Regeneration is manual on purpose: it needs a device, so CI only builds the module. A
stale profile is harmless; a missing one only loses the startup improvement.

## Verify

```bash
adb shell cmd package compile -m speed-profile -f io.github.nevesz.onehz
adb shell dumpsys package io.github.nevesz.onehz | grep -i profile
```

The profile is also validated by the plugin at build time; malformed rules fail
`assembleRelease`.

# Compatibility

## Tested configurations

| Item | Samsung | POCO |
|---|---|---|
| Device | Galaxy S25+ (`SM-S936B`, `pa2q`) | `2412DPC0AG` (`rodin`) |
| Android | 17 (API 37) | 16 (API 36) |
| Software | One UI 9.0 | HyperOS 3.0 (`OS3.0.304.0.WOJMIXM`) |
| Panel rates | 120, 80, 60, 48, 40, 30, 26.67, 24, 20, 10 Hz | 120, 90, 60, 30 Hz |
| Control route | `refresh_rate_mode` + `peak/min` | `secure/miui_refresh_rate` |
| Shizuku | thedjchi fork `v13.7.0-thedjchi` | `14.0.0.r2664-compat` |
| OneHZ | 1.0.1 | 1.0.1 |

Everything else is **untested**.

## Eligibility gate

`DisplayGate.evaluate()` accepts a device only when all checks pass:

1. manufacturer/brand is **Samsung** or **Xiaomi/Redmi/POCO**;
2. the vendor route exists:
   - Samsung: `Settings.Secure.refresh_rate_mode`;
   - Xiaomi: `Settings.Secure.miui_refresh_rate` or `user_refresh_rate`;
3. the display exposes **at least two distinct refresh rates**.

**LTPO is not required.** A 120/90/60/30 panel is accepted. If any check fails,
OneHZ shows “Display not supported” with the reason and does not write anything.

Check the device locally:

```powershell
adb shell getprop ro.product.manufacturer
adb shell getprop ro.product.model
adb shell getprop ro.product.brand
adb shell getprop ro.build.version.release
adb shell getprop ro.build.version.oneui
adb shell getprop ro.mi.os.version.name
adb shell dumpsys display | Select-String "mSupportedRefreshRates"
adb shell settings get secure refresh_rate_mode
adb shell settings get secure miui_refresh_rate
adb shell settings get secure user_refresh_rate
```

## Supported devices

- Samsung phones with at least two refresh rates.
- Xiaomi/Redmi/POCO phones on HyperOS/MIUI with at least two refresh rates.
- Tested only on the S25+ and the POCO above.

## Panel limitations

### 30 Hz brightness on HyperOS

On the tested POCO (`2412DPC0AG`), 30 Hz is visibly darker than 60/120 Hz at the same
system brightness. The difference is generated by the panel/vendor PQ when the display
mode changes, not by Android:

- `screen_brightness` and `debug.tracing.screen_brightness` are identical at 30 and 120 Hz;
- the framebuffer is identical (same content, same pixels);
- the reported backlight is identical;
- the vendor dimming mode (`DisplayFeatureManager` `setScreenEffect`) and
  `cmd display set-brightness` do not change it;
- Shizuku runs as `shell` (UID 2000, no root), and the vendor sysfs/property routes that
  could change the panel gamma are denied by SELinux.

OneHZ therefore cannot equalize the brightness. Keeping 30 Hz is supported, and the
profile editor shows a warning on Xiaomi devices when a step uses 30 Hz. At maximum
brightness there is no headroom to compensate upward, and dimming 60/120 Hz to match
30 Hz would only make the whole screen darker.

## Not supported / untested

- other manufacturers (blocked by the gate);
- devices with a single refresh rate (blocked);
- Samsung without `refresh_rate_mode` (blocked);
- Xiaomi without `miui_refresh_rate`/`user_refresh_rate` (blocked);
- AOD brightness on Xiaomi (Samsung-only; hidden);
- foldables and cover screens (untested);
- tablets (untested);
- WQHD+ mode on the tested Samsung (untested);
- Android 12–15 (minSdk allows them, but only Android 16 and 17 were tested);
- HyperOS 1/2 (the route fallback exists, but only HyperOS 3 was tested);
- other Shizuku versions.

## Firmware dependencies

Samsung:

- `refresh_rate_mode`;
- `peak_refresh_rate`, `min_refresh_rate`;
- `debug_aod_brightness`;
- Samsung battery-saver rate keys (`pms_*`/`psm_*`).

Xiaomi/HyperOS:

- `miui_refresh_rate` (HyperOS 2/3);
- `user_refresh_rate` (HyperOS 1 fallback).

A future firmware update may rename, restrict, or remove these settings. In that case,
OneHZ fails closed and shows the detected state. Please report the firmware build and
the diagnostic report.

## Shizuku

- Tested with the thedjchi fork on the S25+ and a compatible fork on the POCO.
- The official Shizuku should work because the app uses the standard API, but it was
  not tested.
- After a reboot, Shizuku may need to be started again through wireless debugging or
  ADB. OneHZ reconnects when Shizuku becomes available.

## Reporting compatibility

Include:

- model, product, Android, One UI/HyperOS, build, security patch;
- panel rates from `dumpsys display`;
- route values (`refresh_rate_mode`, `miui_refresh_rate`, `user_refresh_rate`);
- Shizuku version;
- whether the gate shows OK;
- what works and what does not.

Do not post personal data.
